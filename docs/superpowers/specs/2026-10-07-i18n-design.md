# 다국어 지원 (한국어·영어·일본어) 설계

작성일: 2026-10-07 · 상태: 설계 승인됨, 구현 전

구현하면서 본 스펙(`2026-10-01-yugitokenbar-design.md`)의 3절(데이터 파이프라인), 4절(구조), 6절(화면·설정), 7절(오류), 8절(테스트)에 같은 커밋으로 합친다. 합친 뒤에는 본 스펙이 기준이다.

## 1. 목적

UI 문구와 카드 정보(카드명·효과·속성·종족/타입·팩 이름)를 한국어·영어·일본어로 보여 준다. 컬렉션 대상(한국 정발 정규 부스터 100팩, 8,172종)·cid·등급·팩 구성·세이브는 언어와 상관없이 그대로다. 카드 이미지와 이미지 출처는 바꾸지 않는다.

## 2. 결정 사항

| 항목 | 결정 |
|---|---|
| 기본 언어 | 시스템 따르기 |
| 지원하지 않는 시스템 언어 | 영어 |
| 언어 전환 반영 | 재시작 후 |
| EN/JP 팩 이름 | 대응하는 원판(OCG·TCG) 팩명으로 매핑 |
| 텍스트가 없는 카드 | 카드 단위로 EN → JP → KO (JP는 JP → KO) |
| 레어리티 표기 | N·R·SR·UR·SE 그대로 (언어 무관) |
| 큰 숫자 축약 | K·M 유지 (언어 무관). 천 단위 구분·날짜는 언어를 따른다 |
| JA/EN 수집 | 카드별 상세 페이지 (Konami, 1초 간격) |
| 버전 | 0.5.0 (마이너) |

## 3. 카드 데이터

### 파일

`Resources/cards_KO.json`·`cards_JP.json`·`cards_EN.json`. 기존 `cards.json`은 없앤다. 형식은 지금과 같고(팩 하나·카드 하나가 한 줄), 세 파일 모두 같은 팩 목록·같은 cid·같은 순서다.

- 세 파일이 같은 필드: 팩의 `pid`·`date`·`cards`·`setCode`·`imageURL`, 카드의 `tier`·`imageId`·`level`·`atk`·`def`·`scale`·`kind`·`summons`, `materials`의 개수와 `cid` 소재(`cid`·`count`).
- 언어마다 다른 필드: 팩 `name`, 카드 `name`·`attr`·`type`·`text`·`pendulum`, `materials`의 `name`·`rule` 소재(`count` 포함. EN은 "2 \"Gladiator Beast\" monsters"처럼 수가 문장 안에 있다).
- JP·EN의 마법·함정은 `attr`에 아이콘 칸 값("通常魔法"·"Normal Spell" 등)을 넣고 `type`은 뺀다.
- 새 필드(언어 무관 코드, KO에서 계산해 세 파일에 같게 쓴다):
  - `kind`: `"spell"`·`"trap"`. 몬스터는 생략한다. KO `attr`가 "마법"·"함정"인지로 정한다.
  - `summons`: 몬스터의 KO `type`을 `/`로 나눈 칸 중 의식·융합·싱크로·엑시즈·펜듈럼·링크를 `ritual`·`fusion`·`synchro`·`xyz`·`pendulum`·`link`로 바꾼 배열(시대 순). 없으면 생략한다.

EN 파일 예시(문자열 값은 실제 파싱 결과와 다를 수 있음):

```json
"4043":{"name":"Gaia the Dragon Champion","attr":"WIND","level":7,"type":"Dragon / Fusion","atk":"2600","def":"2100","text":"","imageId":66889139,"tier":3,"summons":["fusion"],"materials":[{"cid":4044},{"cid":4045}]}
```

### 대체 규칙

이름이 비어 있으면 그 언어에 그 카드가 없는 것으로 본다. 그런 카드는 언어별 필드 전부를 다음 언어에서 가져온다(EN → JP → KO, JP → KO). 필드 하나만 섞지 않는다. 빌드 스크립트가 대체된 카드를 `cid 이름 (→ JP)` 형식으로 모두 출력하고 개수를 요약한다.

### 융합 소재

JP·EN도 효과 첫 줄이 소재 줄이다. KO 카드에 `materials`가 있으면 그 언어 텍스트의 첫 줄을 떼어 `＋`·`+`로 나눈다. EN은 ` + `(앞뒤 공백), JP·KO는 `＋`로 나눈다. 조각 수가 KO 소재 수와 같으면 같은 자리끼리 맞춰 `cid` 소재는 KO 그대로, `name`·`rule` 소재는 그 언어 조각으로 채운다(`"…"`·`「…」` 따옴표는 `name`에서 벗기고, 끝의 `× N`·`×３`은 `count`). 다르면 KO 소재를 그대로 두고, `name`·`rule` 소재가 있는 카드만 출력한다(전부 `cid`면 문자열이 화면에 안 나와서 상관없다). 어느 경우든 그 언어 텍스트의 첫 줄은 뗀다. `cid` 소재는 앱이 현재 언어의 카드명으로 그린다.

### 원판 팩명

카드 상세 페이지에는 그 카드가 수록된 팩(이름·발매일) 목록이 있다. 한국 팩마다 수록 카드들의 그 언어 수록 팩 이름을 세어 가장 많은 것을 팩 `name`으로 쓴다(동률이면 발매일이 빠른 쪽). 매핑을 전부 `KO 이름 → JP/EN 이름 (겹친 수/팩 카드 수)`로 출력한다. 틀린 매핑은 스크립트 상단의 덮어쓰기 표(`PACK_NAME_OVERRIDES = {"ja": {pid: 이름}, "en": {...}}`, 처음엔 비어 있음)로 고친다.

## 4. 빌드 스크립트 (`tools/build-cards.py`)

```
python3 tools/build-cards.py [--lang ko|ja|en|all] [--reformat]
```

- `--lang` 기본값은 `all`(ko → ja → en 순서). 출력 경로 위치 인자는 없앤다.
- `ko`: 지금 흐름 그대로(팩 목록·팩 페이지·YGOPRODeck·Yugipedia). 출력은 `cards_KO.json`이고 `kind`·`summons`를 더한다.
- `ja`·`en`: `cards_KO.json`의 cid마다 `card_search.action?ope=2&cid=<cid>&request_locale=<ja|en>`을 **1초 간격**으로 받아 이름·속성·레벨·종족/타입·ATK/DEF·효과·펜듈럼 효과·수록 팩 목록을 파싱한다. KO에 없는 cid는 받지 않는다.
- **이어 받기**: 파싱 결과를 `tools/cache/<ja|en>.jsonl`에 한 줄(`{"cid":…,"info":{…},"packs":[[이름, 날짜], …]}`)씩 바로 덧붙인다. 다시 실행하면 이미 있는 cid는 건너뛴다. HTML 원문은 저장하지 않는다. `tools/cache/`는 gitignore한다. 캐시를 처음부터 다시 받으려면 파일을 지운다.
- `--reformat`: 네트워크 없이 세 파일을 지금 형식으로 다시 쓴다(있는 파일만). `kind`·`summons`는 KO에서 다시 계산해 세 파일에 넣는다.
- **검증**(실패 시 non-zero 종료): KO는 지금 검증(100팩, 빈 이름, 팩 이미지)과 같다. JP·EN을 쓴 뒤에는 세 파일의 팩 pid 순서·팩 카드 목록·카드 cid 순서와 언어 무관 필드가 같은지, 모든 카드에 이름이 있는지 확인한다.
- 요청 수는 언어당 8,172건이라 처음 실행에 5~9시간이 걸린다. 백그라운드에서 돌리고 끊기면 같은 명령을 다시 실행한다.

## 5. 앱

### 언어 결정

- `AppLanguage`(`system`·`ko`·`en`·`ja`). 설정값은 앱 도메인 `UserDefaults`의 `AppleLanguages`에 저장한다(`ko`면 `["ko"]`, 시스템 따르기는 키 삭제). macOS가 다음 실행부터 이 값으로 번들 현지화와 `Locale.current`를 정한다.
- 이번 실행의 언어: `Bundle.preferredLocalizations(from: ["en", "ko", "ja"]).first`. 목록 맨 앞이 `en`이라 지원하지 않는 언어(fr·de 등)는 영어가 된다(2026-10-07 확인). UI 문구와 카드 파일이 모두 이 값을 따른다.
- Info.plist: `CFBundleDevelopmentRegion = en`, `CFBundleLocalizations = [ko, en, ja]`. 이렇게 해야 번들 문구도 지원하지 않는 언어일 때 en.lproj로 간다.

### 카드 로더

- `CardDB.bundled()`가 이번 실행 언어의 `cards_<KO|JP|EN>.json`을 번들 → 저장소 `Resources/` 순서로 찾는다. 로드 실패는 지금처럼 원인을 담은 `fatalError`다.
- `CardInfo`에 `kind: String?`·`summons: [String]?`를 더한다. `CardKind` rawValue는 `monster`·`spell`·`trap`이다. `matches(kind:)`는 `kind`와 `summons`를 보고, 종류 메뉴 값은 코드값이며 화면 이름은 현지화 문자열이다. `levelName`은 `summons`에 `xyz`가 있으면 랭크, `link`면 링크, 그 밖은 레벨이다. `attr`·`type`은 표시에만 쓴다.
- 세이브(`GameState`)는 cid만 저장하므로 바꾸지 않는다. 종류 필터(`@State`)는 저장되지 않는다. 덱 이름 "새 덱 N"은 만들 때의 언어로 저장되고 이후 바뀌지 않는다.
- 검색과 이름순 정렬은 현재 언어의 카드명으로 한다.

### UI 문구

- `Resources/ko.lproj`·`en.lproj`·`ja.lproj`의 `Localizable.strings`. 키는 지금 코드의 한국어 문장 그대로다(보간은 `%lld`·`%@` 형식). `ko.lproj/Localizable.strings`는 주석만 있는 빈 파일이라 키가 그대로 보인다. SwiftPM 리소스(`Bundle.module`)를 쓰지 않으므로 `Text("…")`·`Button("…")` 같은 리터럴은 코드를 고칠 필요가 없다.
- `String`을 만들어 넘기는 곳(정렬 이름, 종류·소환법 이름, 시대 소환법, 레벨/랭크/링크, 팩 개봉 제목, "새 덱 N", 확인창 문구, `hoverHint` 등)은 `String(localized:)`로 바꾼다.
- 번역 용어: 유희왕 용어는 영어는 TCG 공식 표기(Spell·Trap·Xyz·GY·Fusion Materials·Winged Kuriboh 등), 일본어는 OCG 공식 표기(魔法·罠·エクシーズ·墓地·融合素材·ハネクリボー 등)로 옮기고 일반 단어로 의역하지 않는다. 용어집은 구현 계획 작업 4의 규칙 7.
- `build-app.sh`가 lproj 세 개와 카드 파일 세 개를 `Contents/Resources/`에 복사한다.
- `Usage/`(PokeTokenBar 복사본)에는 화면에 보이는 한국어 문구가 없어서 고치지 않는다. 한도 이름("Codex other" 등)은 영어 고유명사라 모든 언어에서 그대로 보인다.
- 한계: 번역은 `.app` 안에서만 보인다(`swift run` 실행 파일 옆에는 lproj가 없음). `swift run`은 UI가 항상 한국어이고 카드 언어만 설정을 따른다. 언어별 QA는 `scripts/build-app.sh` 뒤 `YTB_STATE_DIR=$PWD/qa-state build/YugiTokenBar.app/Contents/MacOS/YugiTokenBar -AppleLanguages '(en)'`로 한다. 설정의 언어 메뉴를 시험할 때는 끝나고 시스템 따르기로 되돌린다(번들 ID가 설치된 앱과 같아 그 설정을 같이 쓴다).

### 숫자·날짜

`shortCoins`(K·M, `en_US` 고정)와 `shortTokens`는 그대로 둔다. 천 단위 구분과 날짜 표시는 `.formatted()`(`Locale.current`)를 쓴다. 파일 이름 날짜 같은 고정 형식(`SaveTransfer.stamp`)은 그대로 둔다.

### 설정 화면

일반 묶음에 [언어] 메뉴를 넣는다. 항목은 시스템 따르기 / 한국어 / English / 日本語이고, 언어 이름은 번역하지 않는다. 바꾸면 메뉴 아래에 "다시 시작하면 적용돼요"를 현재 언어로 보인다.

### 레이아웃

긴 영어·일본어 문자열이 잘리거나 넘치면 해당 뷰에서 `lineLimit`·`minimumScaleFactor`·`fixedSize`로 맞춘다. 패널 폭은 바꾸지 않는다.

## 6. 테스트

- `CardDBTests`(또는 새 `LocalizationTests`):
  - 세 JSON의 팩 pid 순서·팩 카드 목록·카드 cid 집합이 같은지
  - 언어 무관 필드(`tier`·`kind`·`summons`·`imageId`·소재 cid·count)가 같은지
  - 모든 카드에 이름이 있는지(대체 규칙 결과)
  - 같은 `GameState`를 KO·EN·JP DB로 열었을 때 `ownedDistinct`·전체 카드 수·`tierProgress`가 같은지
  - `matches(kind:)`·`levelName`이 세 DB에서 같은 결과인지
  - `AppLanguage` 저장/삭제와 `en` 대체(지원하지 않는 언어 → `en`)
- strings(`LocalizationTests`): `en`·`ja`의 키 집합이 같고, 키마다 포맷 지정자(`%lld`·`%@`)가 같고, 값에 한글이 없는지.
- 키 누락(`tools/sync-strings.py --check`): `swift build`에 `-emit-localized-strings`를 붙여 컴파일러가 실제 타입으로 만든 키(`.stringsdata`, `Usage/` 제외)를 모아 en·ja 파일과 비교한다. 없는 키, 번역 안 된 키(값에 한글), 안 쓰는 키가 있으면 실패한다. 컴파일러가 못 보는 문구(`String`으로 넘겨 `Text(변수)`로 그리는 곳)를 잡으려고 소스의 한글 리터럴(주석·`AppLog`·`fatalError` 제외) 중 키에 없는 것도 실패로 친다(의도한 예외는 스크립트의 `ALLOW`).
- `tools/test_build_cards.py`: 대체 규칙·소재 줄 나누기·팩명 매핑 함수의 assert 자체 검사(네트워크 없음).
- 수동 QA(`.app`, qa-state): 실행 인자 `-AppleLanguages '(ja)'`로 언어 3종을 각각 띄워(설정에 저장되지 않아 설치된 앱과 같은 번들 ID의 실제 설정을 건드리지 않는다) 메뉴바·팝오버·상점·개봉·설정·도감·인스펙터를 확인한다. 긴 문자열이 잘리거나 넘치는지 본다.
