# YugiTokenBar 설계

작성일: 2026-10-01 · 상태: 승인됨 (구현 계획 작성 중 검증 결과 반영)

## 1. 목적

Claude Code·Codex·Gemini·Grok·Pi·oh-my-pi·Cursor 토큰 사용량을 보상으로 바꿔 **한국 정발 유희왕 카드 컬렉션**을 채우는 macOS 메뉴바 앱.
목표: 추억 + 컬렉션 채우기 + 자주 까는 보상 재미. 이번 범위는 **컬렉션과 덱 구성까지** (대결 없음).

### 레어도 매핑 (Konami 레어도 라벨 → 게임 티어, 마스터 듀얼식 4등급)

| 라벨 | 티어 |
|---|---|
| N 노멀 | 1 |
| R 레어 | 2 |
| SR 슈퍼 레어 | 3 |
| UR 울트라 레어 | 4 |
| SE 시크릿(PSE·QCSE·10000 SE 포함) · UL 얼티미트 · HR 홀로그래픽 · P | 5 (SE) |

등급 색은 N `#5C6470`(다크 `#8E96A3`) · R `#4A90E2` · SR `#F5C451` · UR `#B05CFF` · SE `#FF3D7F`, 미획득 `#A0A0A0`(`Rarity`). 등급은 어디서나 등급 색으로 채운 알약(`RarityPill`)으로 보여준다(팩 개봉, 컬렉션 그리드·수록 팩). 알약 글자는 대비 4.5:1을 넘도록 라이트의 어두운 N 위에서만 흰색이고, 다크의 밝힌 N·나머지 등급·미획득 회색 위에서는 검정이다. R 이상은 팩 개봉 때 등급 색으로 빛난다. 카드에 마우스를 올리고 움직이면(`cardTilt(tier:)`, `CardImageView.swift`) 실물 카드처럼 커서 쪽으로 최대 ±8° 기울고(`rotation3DEffect` x·y축, perspective 0.5) 스프링(`interpolatingSpring(stiffness: 180, damping: 16)`)으로 따라와 방향을 바꾸거나 벗어날 때 한두 번 출렁인다. 1.03배로 커지고 그림자는 기울기 반대쪽으로 밀린다. 커서를 따라가는 흰 반사(`plusLighter`, N·R 0.14, SR 0.22)를 겹치고, UR·SE는 기울기에 따라 돌아가는 무지개 홀로그램을 덧입힌다. 동작 줄이기(또는 설정 [애니메이션 끄기])면 기울기 없이 반사만 약하게. 수치는 modifier 안 상수다. 적용: 컬렉션 상세 큰 이미지, 팩 개봉 카드(앞면이 보인 뒤, 뒤집기 회전 바깥), 요약 최근 획득 썸네일(각도 절반). 등급은 카드에 붙어 있다(`CardInfo.tier`, 라벨은 `CardInfo.rarity`). `build-cards.py`가 Konami 레어도를 N 1·R 2·SR 3·UR 4로, 그 밖(SE·PSE·QCSE·UL·HR 등)을 5 = SE로 매기고, 재수록 카드는 수록 팩 중 가장 높은 등급을 카드에 옮긴다(예: 유벨은 환영의 어둠 N, 팬텀 나이트메어 QCSE → SE). 팩 표지 몬스터(Yugipedia `cover_card`, `build-cards.py`의 `COVER_SE` 98종)는 어느 팩에서 나오든 SE로 올린다. 표지가 마법·함정인 악몽의 미궁·어둠의 유산과 「영원한 화염」의 마의 덱 파괴 바이러스, 한글판에 없는 「장렬한 전투」 표지 2장은 뺀다. Konami 원래 표기(UL 등)는 남기지 않는다. 실측 티어 분포(100팩): 4,758 / 1,730 / 896 / 488 / 300. 모든 팩에 SE가 있다. 검투사의 급습·광속의 스타더스트는 UR이 표지뿐이었어서 UR이 없다(UR 슬롯은 SR로 내려간다).

## 3. 데이터 파이프라인 (`tools/build-cards.py`, 수동 1회 실행 후 결과 커밋)

1. Konami 한국 DB 상품 목록(`card_list.action?request_locale=ko`)에서 `【정규 부스터 팩】` 그리고 발매일 < 2026-07-15 인 상품 중 이름에 "어시스트 팩"·"익스팬션 팩"·"얼티미트 스페셜 팩"이 없는 것을(100팩) 고른다. 미니 팩은 20장 이하에 노멀이 없어 팩 규칙(노멀 보장)에 안 맞는다.
2. 각 팩 페이지(`card_search.action?ope=1&sess=1&pid=<pid>&rp=99999&request_locale=ko`)에서 카드별 `cid`, 한국어 이름, 속성, 레벨(엑시즈는 랭크, 링크는 링크 수), 종족/타입(마법·함정은 장착/지속/속공 등, 없으면 "일반"), ATK/DEF(링크는 DEF 없음), 효과 텍스트(`&lt;br&gt;`로 이스케이프된 줄바꿈도 풀어 준다), 펜듈럼이면 P스케일 `scale`과 펜듈럼 효과 `pendulum`(없으면 생략), 레어도 라벨(행에 여러 개면 첫 번째)을 추출한다(티어로 바꿔 카드의 `tier`에 넣는다). 값이 없는 칸은 JSON에서 뺀다. `cid`로 중복을 없앤다. 융합 몬스터는 효과 텍스트 첫 줄(소재 줄, `＋`로 나뉨)을 `materials` 배열로 뗀다: `"이름"`은 100팩 카드면 `{"cid"}`, 아니면 `{"name"}`(미노타우로스 등 15종), 그 밖("전사족 몬스터", `"섀도르" 몬스터`, `"A"이나 "B"`)은 `{"rule"}` 원문, 뒤의 `× N`은 `count`. 소재를 뗀 `text`는 바닐라 융합이면 빈 문자열이다. NEX로만 소환하는 2종과 천극휘함－베어트론(첫 줄이 `.`로 끝나는 효과문)은 `materials`가 없다. 융합 286종 중 소재가 있는 건 283종, 전부 `cid`인 건 83종. 팩 페이지에는 카드 번호(LOB-K001 등)가 없어서 화면에 번호는 보여주지 않는다(팩 안 순서는 정렬에만 쓴다).
3. YGOPRODeck `cardinfo.php?misc=yes` 전체를 한 번 받아 `misc_info.konami_id == cid`로 이미지 ID(passcode)를 연결한다. 팩 이미지는 `cardsets.php`의 TCG 팩 중 카드가 가장 많이 겹치는 팩(겹친 수 ÷ 두 팩 중 큰 쪽 카드 수)의 `set_code`를 `setCode`로 넣는다. 봉투 이미지 `imageURL`은 Yugipedia의 한글판 `<setCode>-BoosterKR.*`(폭 600px 썸네일, 원본이 더 작으면 원본)이고, 없으면 YGOPRODeck 영문판 `images/sets/<setCode>.jpg`다. 런타임에 캐시한다.
4. 출력 `Resources/cards.json` (저장소 루트. SwiftPM 리소스가 아니며, `.app`에서는 `Contents/Resources/`로 복사한다):
   ```json
   { "packs": [ { "pid": "71101000", "name": "푸른 눈의 백룡의 전설", "date": "2003-12-09", "setCode": "LOB", "imageURL": "https://ms.yugipedia.com//4/4b/LOB-BoosterKR.png",
                  "cards": [ 4711, 4007, … ] } ],
     "cards": { "4007": { "name": "푸른 눈의 백룡", "attr": "빛", "level": 8,
                          "type": "드래곤족/일반", "atk": 3000, "def": 2500,
                          "text": "…", "imageId": 89631139, "tier": 4 },
                "4043": { "name": "용기사 가이아", …, "text": "", "materials": [ { "cid": 4044 }, { "cid": 4045 } ] },
                "7287": { "name": "검투수 헤라클레이노스", …, "materials": [ { "cid": 7286 }, { "rule": "\"검투수\"라는 이름이 붙은 몬스터", "count": 2 } ] } } }
   ```
   `packs`는 발매일 오름차순이다. 파일은 팩 하나·카드 하나가 한 줄이다(diff용). `--reformat`은 받아 오지 않고 기존 파일을 이 형식으로만 다시 쓴다(팩의 등급을 카드로 옮기기와 소재 분리도 이때 한다. 이미 옮기거나 뗀 것은 그대로).
5. 검증 출력: 팩 수(100), 팩별 카드 수/레어도 분포, 고유 카드 수, **이미지 미매칭 카드 목록**(미매칭은 수동 확인). 실패 시 non-zero 종료.
6. Konami 요청은 1초 간격.

### 토큰 적립

- 토큰 = input + output + cacheWrite + cacheRead (PokeTokenBar와 동일).
- 집계 대상(`TodayUsageReader.read` = `TodayUsage.read`와 같은 결과, 이 Mac의 로컬 로그만. 오늘 바뀐 Claude JSONL은 수십~수백 MB라 파일마다 수정 시각·크기가 그대로면 다시 파싱하지 않고 메모리에 둔 결과를 쓴다. 쓰는 중인 세션 파일은 매번 통째로 다시 읽는다): Claude Code(`~/.claude/projects` 등), Codex(`~/.codex/sessions`·`archived_sessions`), Gemini, Grok(`~/.grok/sessions`), Pi(`~/.pi/agent/sessions`), oh-my-pi, Cursor. Cursor는 실앱·`PTB_PARITY=1`에서만 대시보드 API(`CursorUsageAPI`, Cursor 로그인 토큰)를 쓰고, 실패하거나 개발 실행이면 로컬 `state.vscdb`를 읽는다. API 캐시는 세이브 폴더의 `cursor-usage-api-cache.json`.
- 매 갱신마다 오늘의 provider별 누적 토큰을 구하고, `claimedToday.byProvider`와의 **양수 차이만** 적립한다. 날짜가 바뀌면 원장을 새로 시작한다 (PokeTokenBar `claimedTodayTokensByProvider` 방식). 그때 원장 날짜(`claimedDate`)부터 어제까지 날짜별 누적도 함께 읽어(`TodayUsageReader.read(since:)`, 최대 `catchUpDays` = 30일. Claude Code가 기본으로 30일 지난 기록을 지운다), 원장 날짜는 원장과의 양수 차이만, 그 뒤 앱이 꺼져 있던 날은 전부 적립한다. 자정 직전 마지막 갱신 뒤 쓴 몫도 여기서 들어온다.
- 첫 실행 시 오늘 누적치를 원장에 그대로 기록한다 → 설치 전 사용량은 적립하지 않는다.
- **원장은 같은 날 안에서 절대 내려가지 않는다.** 일시적으로 작은 값이 읽혀도 원장을 낮추지 않아야 나중에 같은 토큰을 두 번 적립하지 않는다.
- 적립된 delta는 `coinRemainder`에 더해 10,000 토큰마다 `coins += 1`로 환산하고(나머지는 이월), 같은 delta를 `dropProgress`(무료 카드용)에도 더한다.

### 저장

`~/Library/Application Support/YugiTokenBar/state.json`, 원자적 쓰기, 쓰기 전 직전 파일을 `state.json.bak`으로 보존.

```
{ coins, coinRemainder, dropProgress,
  owned: { cid: 보유 장 수(상한 없음) },
  claimedToday: { date, byProvider },
  pendingFree: <열지 않은 무료 카드 = 배지 숫자>,
  packStamp: <코인으로 산 팩 수, 10마다 0>, freePacks: <안 쓴 무료 팩>,
  lastBoughtPid: <코인으로 마지막에 산 팩 pid. 없으면 로그에서 찾는다>,
  favorites: [ 즐겨찾기 cid ],
  autoSellDuplicates: <설정: 중복 카드 자동 판매>,
  fusionOnly: <설정: 융합 몬스터는 융합으로만. 기본·키 없음 = false>,
  eraLimit: <설정: 시대 범위, 시대 이름. 기본·키 없음 = "GX">,
  partnerUnlocked: <파트너 해금. 「날개 크리보」를 처음 가질 때 true, 팔아도 유지. 기본·키 없음 = false>,
```

- 디코딩에 실패하면 원본을 `state.corrupt-<epoch>.json`으로 보관하고 `.bak`에서 복구한다. 둘 다 실패하면 새 상태로 시작한다.
- 환경변수 `YTB_STATE_DIR`가 있으면 그 폴더를 쓴다(개발·QA 때 실제 세이브와 분리).

### 내보내기·가져오기

- 내보내기 파일 `YugiTokenBar-Save-YYYYMMDD.json` = 봉투 `{ format: "yugitokenbar.save", schema: 1, appVersion, exportedAt, state }`. 상태 디코딩이 빠진 키를 기본값으로 채워 아무 JSON이나 읽히므로, 기본값이 없는 `format`/`schema`로 먼저 가린다. 8MB 초과, 다른 format, 더 높은 schema는 거부한다.
- 가져오기는 들어올 세이브와 지금 세이브의 수치(보유 종류 수, 코인)를 보여주고 확인을 받는다(Return = 취소). 바꾸기 전에 지금 세이브를 같은 봉투 형식으로 세이브 폴더(`YTB_STATE_DIR`를 따름)에 `state.import-backup-YYYYMMDD-HHmmss.json`으로 남긴다. 이 파일도 [가져오기]로 되돌릴 수 있다. 백업은 지우지 않는다.
- 적립 원장(`claimedDate`, `claimedByProvider`)은 이 Mac의 값을 유지한다. 다른 Mac의 원장을 쓰면 오늘 토큰을 다시 적립한다. 파트너 해금은 둘 중 하나라도 해금이면 유지하고, 파트너 표시 설정(`partnerEnabled`·`partnerSize`·`partnerOrigin`)도 이 Mac 값을 쓴다(`GameState.withLedger`).

## 5. 경제·뽑기 규칙

### 밸런스 상수

| 상수 | 값 |
|---|---|
| `tokensPerCoin` | 10,000 |
| `packPrice` | 1,000코인 (= 10M 토큰) |
| `packsPerFreePack` | 10 (코인으로 10팩 사면 랜덤 무료 팩 1개) |
| `tokensPerFreeCard` | 10,000,000 |
| `freeOpenBatch` | 5 (무료 카드 한 번에 여는 장 수) |
| `cardsPerPack` | 5 (노멀 3 + 노멀 또는 레어 1 + 레어 이상 1) |
| `slot4RareChance` | 4번째 장이 노멀 대신 R일 확률 30% |
| `monstersPerPack` | 2 (한 봉투에서 보장하는 몬스터 장 수) |
| `slot5Weights` | R 70% / SR 18% / UR 10% / SE 2% (50팩에 1장) |
| `freeWeights` | 무료 카드: N 70% / R 23% / SR 5% / UR 1.5% / SE 0.5% |
| `sellPrice` | 1장당 N 20 / R 50 / SR 150 / UR 400 / SE 1,200 코인 |
| `maxCopiesInDeck` | 3 (덱에 같은 카드 최대 장 수, 유희왕 규칙. 미보유도 가능) |
| `deckSize` | 40~60 (메인 덱 권장 장 수, 표시만) |

하루 50M 토큰 → 무료 5장 + 5팩(25장).

### 무료 카드

`dropProgress`가 10M을 넘을 때마다 1장이 `pendingFree`에 **쌓이기만 한다**(자동으로 뽑지 않는다). 팝오버의 [무료 카드 N장 · 열기]를 누르면 최대 `freeOpenBatch`(5)장씩 **전체 8,172종에서 `freeWeights`로 티어를 고르고 그 티어 안에서 균등 무작위**로(티어가 비면 팩처럼 아래 → 위 티어로, 융합 전용 카드는 뺀다) 뽑아 패널 안 개봉 화면에서 보여준다. 보유 수 상한이 없어 이미 가진 카드도 나온다.

### 팩 구매

해금 없이 100팩 중 무엇이든(완료한 팩도) 살 수 있다. 코인으로 산 팩이 `packsPerFreePack`(10)개가 될 때마다 무료 팩 1개(`freePacks`)가 쌓인다. 팝오버의 [무료 팩 N개 · 열기]를 누르면 **정규 부스터 100팩 중 하나를 균등 무작위로** 골라 1봉투를 연다(개봉 화면 제목 "무료 팩 · 팩 이름"). 무료 팩으로 깐 건 다음 무료 팩 카운트에 세지 않는다. 한 번에 1팩씩만 사며, 버튼에는 가격(`ⓒ 1,000`)을 표시하고 코인이 부족하면 비활성화한다.
슬롯 1~3은 티어 1, 슬롯 4는 `slot4RareChance`(30%)로 티어 2 아니면 티어 1, 슬롯 5는 `slot5Weights`로 티어를 고른다. 슬롯 1~`monstersPerPack`(2)은 몬스터만 뽑아 한 봉투에 몬스터가 최소 2장 나온다(마법·함정만 나오는 봉투 없음). 모든 팩에 노멀 몬스터가 13장 이상이라 이 슬롯이 다른 티어로 올라가는 일은 없다(`CardDBTests`가 검증). 무료 카드에는 적용하지 않는다.

### 판매

컬렉션 창에서 보유한 카드를 1장씩 판다. 가격은 `sellPrice[카드의 tier]`다. 0장이 되면 컬렉션에서 빠진다(마지막 1장은 확인 후 판매). 툴바의 [중복 모두 팔기]는 카드마다 1장만 남기고 나머지를 한꺼번에 판다(장 수와 받을 코인을 확인 후. 융합 전용 설정이 켜져 있으면 융합 소재는 필요한 최대 장 수만큼 남긴다(`Game.keep`, `CardDB.materialNeed`), 도움말과 확인창에도 그렇게 적는다). 팩 1개를 다 팔아도 기대값 ≈ 215코인이라 `packPrice`(1,000)보다 작다.

### 덱

컬렉션 창에서 덱을 여러 개 만든다. **미보유 카드도 넣을 수 있고**(목표 덱), 카드마다 `maxCopiesInDeck`(3)장까지다. 덱 장 수는 제한하지 않고 `deckSize`(40~60)는 권장으로만 보여준다. 덱 화면에서 보유 수가 덱에 넣은 장 수보다 적은 카드는 미보유처럼 흐리게 보여서 더 모아야 할 카드를 알 수 있다. 덱을 지워도 카드는 그대로다. 덱은 세이브(`decks`)에 저장된다.

### 융합

소재가 전부 100팩 카드인 융합 몬스터(83종. `Game.fusionMaterials`가 nil이 아닌 것, 소재 cid → 장 수)는 컬렉션 상세의 [융합]으로 만든다. 「융합」 마법 카드(`CardDB.fusionSpell` = 4837, 푸른 눈의 백룡의 전설 SR이라 어느 시대 범위에서도 구할 수 있다)를 1장 이상 가져야 열리고, 이 카드는 소비하지 않는다. 소재를 장 수만큼 소비하고(같은 카드 반복은 그만큼, `count`도 곱한다. 단 마지막 1장은 남겨 컬렉션에서 빠지지 않는다) 1장을 받는다(`source: "융합"`, 중복 자동 판매는 적용하지 않는다). 확인하면 컬렉션 창 위에 우주 느낌의 연출(`FusionAnimationView`, `TimelineView` + `Canvas`로 시간 t 하나에서 모두 계산)이 겹친다: 성운·반짝이는 별 배경 위로 소재 카드(장 수만큼)가 떠다니고 뒤에서 별가루 은하 소용돌이가 생긴다(떠오름 0–3초). 회오리(3–4.4초)에서 소용돌이가 빨라지고 카드가 뒤집히며 잔상을 남기고 하얗게 녹아 빨려 들며, 별 알갱이도 나선으로 빨려 들고 화면이 떨린다. 4.6초에 가운데 빛이 오그라들었다 번쩍이고 테두리 없는 빛 고리 두 겹·별 파편이 퍼진다. 그다음 돌아가는 빛살 속에서 융합 카드가 솟아올라 두 바퀴 돌아 앞면으로 멈추고, 광택(SE는 두 줄)·카드 둘레 반짝임(UR 이상은 무지개 홀로그램)과 이름이 나온다(등급 색은 SR 미만도 SR). 효과는 선 없이 부드러운 빛 점만 쓰고, 흐린 겹 두 개와 선명한 겹을 더해 번지게 그린다. 동작 줄이기 설정이면 마지막 장면만 보인다. 아무 데나 누르면 닫힌다(도중이면 건너뛴다). 소재가 모자라면 비활성. 설정 [융합 몬스터는 융합으로만](`fusionOnly`)이 켜져 있을 때만 버튼이 보이고, 그때 이 83종은 팩(`draw`)과 무료 카드(`drawFree`)에서 뽑히지 않는다(팩 진행도에는 그대로 들어가므로 완료하려면 융합해야 한다). 소재 조건(`rule`)이나 100팩에 없는 소재(`name`)가 섞인 200종과 NEX 2종·베어트론은 설정과 무관하게 팩에서 나온다. 설정이 켜져 있으면 [중복 모두 팔기]와 중복 자동 판매는 소재를 범위 안 융합이 요구하는 최대 장 수(`CardDB.materialNeed`: 사이버 드래곤 3장)까지 중복으로 치지 않는다(`Game.keep`). 꺼져 있으면 1장만 남긴다. 어느 시대 범위에서도 융합 전용 카드의 소재는 같은 범위 안에 있어서(`CardDBTests`가 검증) 런타임에 범위 검사는 없다. 노멀 몬스터 보장은 융합 전용을 빼도 팩마다 13장 이상이라 그대로다.

### 카드 고르기 (`draw(pack, tier)`)

1. 해당 팩에서 그 티어이고 **같은 봉투에서 아직 나오지 않은** 카드 중(종류 제한이 있으면 그 종류만, 융합 전용 카드는 빼고, 보유 수 상한 없음) 균등 무작위로 고른다(한 팩 5장은 항상 서로 다르다).
2. 없으면 한 단계씩 **아래 티어**로 내려가고, 티어 1까지 없으면 **위 티어**로 올라간다.
3. 팩의 모든 카드를 1장 이상 가지면 "완료"(✓)로 표시한다. 완료해도 계속 살 수 있다.

### 완성 예상 (시뮬레이션, 2026-10-02 실데이터, 시드 5개)

VRAINS까지 75팩(6,160종)에서는 "무료 1장 + 1팩" 10,114~11,292회로 완성한다(27팩·2,270종일 땐 4,913~5,753회). 10M 단위이므로 약 1,000~1,100억 토큰이고, 로컬 사용량 추정 월 12억이면 **약 7~8년**이다. 마지막에 남는 UR(팩당 약 10종, 슬롯5 12%)이 대부분을 차지한다(SE 2026-10-06 도입 전, UR·SE를 합쳐 12%이던 때의 계산. SE는 팩당 2~4종에 2%라 특정 SE 1장에 100~200팩이 들어 더 길어진다). 플레이어가 미보유가 가장 많은 팩을 산다고 가정했다. 실사용 후 상수로 조정한다.

## 6. 화면

화면의 코인 금액은 "코인" 글자 없이 `ⓒ 1,000`처럼 표시한다(`coinText`). 10,000 이상은 K·M으로 줄인다(소수 1자리까지, `ⓒ 12.3K`, `ⓒ 1M`, `shortCoins`. 메뉴바 숫자도 같다). 팝오버 안 화면(상점·개봉·설정)의 ‹ 버튼은 Esc 키로도 눌린다.

**외관(라이트·다크)**: 시스템 설정만 따르고 앱 안에 따로 설정을 두지 않는다. 실행 중에 바꿔도 바로 다시 그린다.
- 글자·배경·구분선은 의미 기반 시스템 색(`.primary`·`.secondary`·`.fill`·`.bar`, `Divider`)을 먼저 쓰고, 강조는 시스템 강조색(`accentColor`)을 따른다. 화면마다 `colorScheme`으로 분기하지 않는다.
- 고유한 색은 `CardImageView.swift`의 `Rarity`(등급 색)와 `Palette`(카드 테두리, 주의·위험·융합 글자, 카드 위 배지)에 라이트·다크 값을 같이 둔다(`Color(light:dark:)`). 글자 대비는 WCAG AA 이상(본문 4.5:1, 라이트는 흰 바탕, 다크는 `#2A2A2C` 바탕 기준).
- 카드·팩 이미지는 원본 그대로 둔다. 다크에서는 그림자가 안 보이므로 가장자리에 얇은 밝은 테두리(흰색 20%, 1pt, `Palette.cardRim`)를 두르고, 라이트에서는 테두리 없이 그림자만 쓴다. 카드 위 NEW·코인·개수 배지는 외관과 상관없이 흰 글자가 5:1 이상인 고정 색이다.
- 색을 넣는 진행 막대는 `TintBar`로 직접 그린다(`ProgressView`의 `.tint`는 외관을 바꾸면 풀린다). 설정 화면의 그룹 상자는 `.fill` 대신 `Color.primary` 7%다(`panelScrollBottom`의 `.mask` 안에서 `.fill`은 다크일 때 검게 그려진다).
- 메뉴바 아이콘(SF Symbol)은 메뉴바 색을 따른다. 파트너 날개 크리보는 캐릭터라 컬러 그대로 둔다. 융합 연출은 자체 어두운 배경 위라 외관과 상관없다.

"즐겨찾기"는 즐겨찾기한 카드만 전체 순서대로 보여준다. 사이드바 맨 아래 **덱** 섹션: 헤더의 +로 새 덱("새 덱 N")을 만들고 덱마다 팩 줄처럼 이름·진행 바·"보유/덱 장 수"를 보여준다(보유는 카드마다 덱에 넣은 수와 보유 수 중 작은 쪽의 합, 다 모으면 초록). 그리드의 카드를 덱 줄로 **끌어다 놓으면**(줄이 강조됨) 그 덱에 1장 들어가고, 3장 한도에 걸리면 비프. 카드 우클릭 [덱에 추가 ▸ 덱 이름 · N장]으로도 넣는다(덱이 없으면 [새 덱에 추가]). 덱을 고르면 그리드에 덱의 카드가 팩 순서로 한 카드 한 칸(×장 수)으로 보이고 필터·정렬·검색은 그대로 동작하며, 부제는 "보유 / 덱 장 수장 보유 · 메인 덱 40~60장". 우클릭 [덱에 추가] 목록도 "덱 이름 · 보유/덱 장 수"다. 카드에 마우스를 올리면 왼쪽 위 −로 1장 빼고, 우클릭 [덱에서 1장 빼기]도 된다. 덱 줄 우클릭으로 이름 바꾸기(알림창)·삭제(확인, 보고 있던 덱이면 "전체"로). **여러 장 선택**: 클릭은 한 장, ⌘클릭은 토글, ⇧클릭은 마지막 클릭부터 범위 추가, 빈 곳에서 끌면 러버밴드(화면에 보이는 셀만, ⌘/⇧를 누르고 있으면 기존 선택에 더함), 빈 곳 클릭은 해제. Ctrl클릭은 macOS 우클릭이라 토글에 쓰지 않는다. 선택된 카드를 끌면 선택 전체가 함께 끌리고(미리보기에 장 수 배지) 덱 줄에 놓으면 각각 1장씩 들어간다(세이브는 한 번만 쓴다. `AppModel.addToDeck`·`removeFromDeck`이 여러 장을 받는다). 우클릭 메뉴와 오른쪽 패널("N장 선택됨")의 [덱에 추가 (N장)]·[덱에서 1장씩 빼기 (N장)]도 선택 전체에 적용된다. 상세 정보는 한 장만 선택했을 때 보인다. 툴바 [전체 선택](⌘A)은 지금 보이는(필터·검색된) 카드를 모두 선택한다(러버밴드는 화면에 보이는 셀만 잡는 보완). 덱 화면에선 툴바 [덱에서 빼기](Delete)가 선택한 카드를 1장씩 뺀다. 검색창에 포커스가 있으면 ⌘A·Delete는 검색창 글자에 쓰인다. 사이드바 선택이 바뀌면 선택은 비운다. 시대 범위는 설정에서만 바꾸고 컬렉션 창에는 메뉴도 안내도 두지 않는다. **미보유 카드는 흑백 실루엣**(grayscale 0.8, 밝기 -0.20)으로 보여주고, 마우스를 올리면 이름을 표시한다. 사이드바에서 마지막으로 고른 항목(전체·즐겨찾기·팩·덱)은 기억해서(`dex.scope`) 창을 다시 열면 그대로 열리지만, 그날(로컬 날짜) 처음 열 때는 "전체"로 연다(`dex.scopeDay`). 기억한 팩이 시대 범위 밖이거나 덱이 지워졌으면 "전체".
- **설정** (팝오버 내 화면 전환, 상점과 같은 방식):
  - 일반: [로그인 시 자동 실행] 스위치(`SMAppService.mainApp` 등록·해제, 세이브가 아니라 시스템에 저장). 설치한 `.app`에서만 켤 수 있고 `swift run` 개발 빌드에서는 비활성이다. 시스템이 승인을 요구하면 시스템 설정의 로그인 항목을 연다.
  - 파트너 (베타) (카드 절 아래 별도 절): [바탕화면 파트너] 스위치(기본 켬, 세이브 `partnerEnabled`)와 [크기] 슬라이더(64~256, 16 단위 `PartnerTuning.sizeStep`, `partnerSize`). 해금 전에는 둘 다 비활성이고 "「날개 크리보」 카드를 얻으면 파트너로 함께해요"를 보인다. 스위치가 꺼져 있으면 슬라이더도 비활성.
  - 카드: [중복 카드 자동 판매] 스위치(기본 끔, 세이브에 저장). 켜면 팩·무료 카드에서 이미 가진 카드가 나올 때 그 1장을 바로 `sellPrice`에 판다(보유는 그대로, 최근 획득 기록은 남음. 융합 전용 설정이 켜져 있으면 융합 소재는 필요한 장 수까지 쌓인 뒤에 판다). 개봉 화면에서 그 카드에 `+ⓒ N` 표시. 마우스를 올리면 빨간 `✕ 안 팔기`로 바뀌고 누르면 그 판매를 취소한다(받은 코인을 돌려주고 카드 1장을 되돌림, `Game.unsell`·`AppModel.keepSold`. 그사이 코인을 써서 모자라면 비활성). 이미 쌓인 중복은 건드리지 않는다(컬렉션 [중복 모두 팔기]).
  - 카드: [융합 몬스터는 융합으로만] 스위치(기본 끔, 세이브 `fusionOnly`). 설명 줄에 지금 시대 범위에서 소재를 다 아는 융합 종 수. 켜면 5절 융합.
  - 카드: [애니메이션 끄기] 스위치(기본 끔, 세이브 `animationsOff`). 켜면 시스템 동작 줄이기와 같게 동작한다(`EnvironmentValues.lessMotion` = 설정 || `accessibilityReduceMotion`, 앱이 메뉴바 패널·컬렉션 창에 넣는다): 카드 호버 기울기·출렁임 없음(반사만 약하게), 개봉 카드 뒤집기 즉시·[모두 뒤집기]는 레어도 같이, SR 이상 레어 연출 대신 등급 색 빛만, 융합 연출은 마지막 장면만.
  - 카드: [시대 범위] 메뉴 `DM(의식)까지`·`GX(융합)까지`·`5D's(싱크로)까지`·`ZEXAL(엑시즈)까지`·`ARC-V(펜듈럼)까지`·`VRAINS(링크)까지`·`Modern(지원)까지`(소환법은 `CardDB.eraSummons`)(기본 `GX(융합)까지` = 싱크로 이전 27팩·2,270종, 옛 세이브도 GX로 시작, 세이브에 저장). 고른 시대까지의 앞 팩만(`CardDB.prefix`) 상점·컬렉션 사이드바·전체 카드 수·`ownedDistinct`(팝오버 [컬렉션 n / 전체])·무료 카드 풀·무료 팩에 쓴다. 범위 밖 보유 카드는 지우지 않고 숨기기만 하며(다시 넓히면 돌아온다), [중복 모두 팔기]는 범위 안 카드만 팔고, 덱 진행도(보유/덱 장 수)와 즐겨찾기 수도 범위 안 카드만 세어 그리드에 보이는 것과 맞춘다. 이름·이미지 조회(`cards`)는 전체를 그대로 쓴다. 이름 옆 ? 동그라미에 마우스를 올리면 말풍선(`hoverHint`)으로 "카드·상점·컬렉션이 설정한 시대까지 나와요. / 시대를 옮겨도 카드는 그대로 남아요.", 아래 설명 줄은 지금 범위의 "27팩 · 2,270장". 보던 팩이 범위 밖이 되면 컬렉션은 "전체"로. 컬렉션·상점의 시대 섹션은 받은 팩 범위를 그릴 때마다 지금 DB 에 맞춰 자른다(SwiftUI 가 없어질 섹션을 지우기 전에 몸체를 먼저 그릴 수 있어서). 범위 밖 팩 인덱스로 구매하면(개봉 화면의 [한 팩 더] 등) 코인을 쓰지 않고 거절한다.

- 코인과 무료 카드: 10M 경계, 나머지 이월
- 판매: 중복 자동 판매는 켰을 때 2장째부터만 팔고 끄면 다시 쌓인다; 자동 판매 취소는 코인을 돌려주고 카드를 되돌리며, 코인이 모자라면 거절
- 시대 범위: `DM`이면 팩·카드·보유 종 수·무료 카드·무료 팩이 DM 팩 안에서만, 해제하면 전체로 돌아온다; 범위 밖 중복은 팔리지 않고 덱 진행도·즐겨찾기 수에서 빠진다
- 뽑기: 보유 수 상한 없음, 티어가 비면 아래로 갔다가 위로 이동, 완료 팩도 구매 가능
- 해금 없음: 아무 팩이나 구매 가능, 마지막으로 코인으로 산 팩(`lastBoughtPid`, 무료 카드·무료 팩 제외. 시대 범위 밖이면 첫 팩)
- 덱: 미보유 포함 카드당 3장 한도, 빼기·이름 바꾸기·삭제
- 융합: 설정을 켜면 중복 판매·자동 판매가 소재를 필요한 장 수만큼 남긴다; 「융합」 카드가 없으면 잠김, 소재를 장 수만큼 소비하되 1장은 남기고 1장 지급(「융합」은 남는다), 모자라면 거절, 소재를 모르는 융합은 못 만든다; 설정을 켜면 융합 전용 카드가 팩·무료 카드에서 안 나오고 UR 슬롯은 아래 티어로, 끄면 다시 나온다; 융합 전용 소재는 모든 시대 범위 안
- 저장: 왕복 직렬화, `.bak` 복구
- 데이터: `cards.json` 팩 100개(미니 팩 없음), 고유 8,172종, 시대 7개의 첫 팩 setCode(LOB·SOD·TDGS·REDU·DUEA·COTD·ROTD), 링크·펜듈럼 필드, 융합 소재(283종, 전부 cid 83종, "A"이나 "B"는 rule, 효과에 `＋` 없음), 모든 팩 cid가 `cards`에 존재
- 파트너: 시트 행별 프레임 수·셀 크기, 상태 판정 우선순위와 경계값(80%·1k·100k)·초기화 지난 한도 제외, 분당 토큰(첫 갱신·자정·감소 0, 1분 미만은 1분), 한 번 재생 큐(기준 상태 복귀·중복 방지·클릭 우선), 비행 방향 전환·기준 동작 사이 쉬기(범위 안)·한 번 재생 뒤 쉬지 않음·두리번, 메뉴바 깜빡임, 바탕화면 창 대체 위치(화면 밖·조금만 걸침·nil → 주 화면 오른쪽 아래)와 크기 제한(64~256, 192:208), 해금은 영구(가져오기 포함), 가져오기 때 파트너 표시 설정은 이 Mac 값, 시트가 없으면 파트너 끔, 새 키 없는 옛 세이브

## 9. 범위 밖 (YAGNI)

원격 서버 세션 적립, 다중 계정, 자동 업데이트(설정은 확인과 링크만), 업데이트 알림, 대결, 덱 순서 수동 편집·엑스트라 덱 구분, 레어도별 버전 수집, 스타터/스트럭처/프로모, 업적, 파트너 돌아다니기·커서 따라가기·호버 말풍선·저전력 모드 정지·다른 파트너 선택·메뉴바에서 기준 상태 동작 재생.
