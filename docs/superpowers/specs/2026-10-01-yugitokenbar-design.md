# YugiTokenBar 설계

작성일: 2026-10-01 · 상태: 승인됨 (구현 계획 작성 중 검증 결과 반영)

## 1. 목적

Claude Code·Codex·Gemini·Grok·Pi·oh-my-pi·Cursor 토큰 사용량을 보상으로 바꿔 **한국 정발 유희왕 카드 컬렉션**을 채우는 macOS 메뉴바 앱.
목표: 추억 + 컬렉션 채우기 + 자주 까는 보상 재미. 이번 범위는 **컬렉션과 덱 구성까지** (대결 없음).

## 2. 카드 풀 기준

| 항목 | 기준 |
|---|---|
| 카드 풀 | 한국 정식 발매 **정규 부스터 팩**만 (스타터/스트럭처/프로모 제외) |
| 기간 | 2003-12-09 『푸른 눈의 백룡의 전설』 ~ 2026-07-14 『카오스 오리진즈』 (같은 분류의 미니 팩 ＋1 어시스트·익스팬션 팩, 얼티미트 스페셜 팩은 제외) |
| 규모 | 100팩, 수록 8,195장, 고유 카드 **8,172종**(몬스터 5,033 · 마법 1,719 · 함정 1,420) (2026-10-06 실측. VRAINS까지 75팩은 6,160종) |
| 시대 | DM 1~11팩 · GX 12~27 · 5D's 28~43(싱크로) · ZEXAL 44~51(엑시즈) · ARC-V 52~63(펜듈럼) · VRAINS 64~75(링크) · Modern 76~100(VRAINS 이후). 시대 첫 팩 인덱스는 `CardDB.eraStarts` |
| 표시 이름 | 한국어 카드명 |
| 팩/레어도 | 한국 정발 팩 기준 (Konami DB `t_rid`) |
| 카드 정보/효과 | OCG 기준 한국어 텍스트 |
| 이미지 | YGOPRODeck 영문 실물 이미지, 한국어 텍스트는 이미지 밖에 별도 표시 |

### 레어도 매핑 (Konami 레어도 라벨 → 게임 티어, 마스터 듀얼식 4등급)

| 라벨 | 티어 |
|---|---|
| N 노멀 | 1 |
| R 레어 | 2 |
| SR 슈퍼 레어 | 3 |
| UR 울트라 레어 · SE 시크릿 · UL 얼티미트 · HR 홀로그래픽 | 4 (UR) |

등급 색은 N `#5C6470` · R `#4A90E2` · SR `#F5C451` · UR `#B05CFF`, 미획득 `#A0A0A0`(`Rarity`). 등급은 어디서나 등급 색으로 채운 알약(`RarityPill`)으로 보여준다(팩 개봉, 컬렉션 그리드·수록 팩). 알약 글자는 흰색이고, 밝은 배경인 SR 금색과 미획득 회색 위에서는 검정이다. R 이상은 팩 개봉 때 등급 색으로 빛난다. 카드는 팩마다 그 팩의 라벨과 티어를 가진다. `cards.json`에는 Konami 원래 레어도(SE·UL·HR = 티어 5)가 그대로 있고, `CardDB.load`가 UR로 합친다(라벨도 N/R/SR/UR만 쓴다). 실측 티어 분포(카드마다 가장 높은 티어): 3,703 / 1,273 / 639 / 545.

## 3. 데이터 파이프라인 (`tools/build-cards.py`, 수동 1회 실행 후 결과 커밋)

1. Konami 한국 DB 상품 목록(`card_list.action?request_locale=ko`)에서 `【정규 부스터 팩】` 그리고 발매일 < 2026-07-15 인 상품 중 이름에 "어시스트 팩"·"익스팬션 팩"·"얼티미트 스페셜 팩"이 없는 것을(100팩) 고른다. 미니 팩은 20장 이하에 노멀이 없어 팩 규칙(노멀 보장)에 안 맞는다.
2. 각 팩 페이지(`card_search.action?ope=1&sess=1&pid=<pid>&rp=99999&request_locale=ko`)에서 카드별 `cid`, 한국어 이름, 속성, 레벨(엑시즈는 랭크, 링크는 링크 수), 종족/타입(마법·함정은 장착/지속/속공 등, 없으면 "일반"), ATK/DEF(링크는 DEF 없음), 효과 텍스트(`&lt;br&gt;`로 이스케이프된 줄바꿈도 풀어 준다), 펜듈럼이면 P스케일 `scale`과 펜듈럼 효과 `pendulum`(없으면 생략), 레어도 라벨(행에 여러 개면 첫 번째)을 추출한다. 값이 없는 칸은 JSON에서 뺀다. `cid`로 중복을 없앤다. 융합 몬스터는 효과 텍스트 첫 줄(소재 줄, `＋`로 나뉨)을 `materials` 배열로 뗀다: `"이름"`은 100팩 카드면 `{"cid"}`, 아니면 `{"name"}`(미노타우로스 등 15종), 그 밖("전사족 몬스터", `"섀도르" 몬스터`, `"A"이나 "B"`)은 `{"rule"}` 원문, 뒤의 `× N`은 `count`. 소재를 뗀 `text`는 바닐라 융합이면 빈 문자열이다. NEX로만 소환하는 2종과 천극휘함－베어트론(첫 줄이 `.`로 끝나는 효과문)은 `materials`가 없다. 융합 286종 중 소재가 있는 건 283종, 전부 `cid`인 건 83종. 팩 페이지에는 카드 번호(LOB-K001 등)가 없어서 화면의 번호는 팩 안에서의 순서를 쓴다.
3. YGOPRODeck `cardinfo.php?misc=yes` 전체를 한 번 받아 `misc_info.konami_id == cid`로 이미지 ID(passcode)를 연결한다. 팩 이미지는 `cardsets.php`의 TCG 팩 중 카드가 가장 많이 겹치는 팩(겹친 수 ÷ 두 팩 중 큰 쪽 카드 수)의 `set_code`를 `setCode`로 넣는다. 봉투 이미지 `imageURL`은 Yugipedia의 한글판 `<setCode>-BoosterKR.*`(폭 600px 썸네일, 원본이 더 작으면 원본)이고, 없으면 YGOPRODeck 영문판 `images/sets/<setCode>.jpg`다. 런타임에 캐시한다.
4. 출력 `Resources/cards.json` (저장소 루트. SwiftPM 리소스가 아니며, `.app`에서는 `Contents/Resources/`로 복사한다):
   ```json
   { "packs": [ { "pid": "71101000", "name": "푸른 눈의 백룡의 전설", "date": "2003-12-09", "setCode": "LOB", "imageURL": "https://ms.yugipedia.com//4/4b/LOB-BoosterKR.png",
                  "cards": [ { "cid": 4007, "tier": 4, "label": "UR" } ] } ],
     "cards": { "4007": { "name": "푸른 눈의 백룡", "attr": "빛", "level": 8,
                          "type": "드래곤족/일반", "atk": 3000, "def": 2500,
                          "text": "…", "imageId": 89631139 },
                "4043": { "name": "용기사 가이아", …, "text": "", "materials": [ { "cid": 4044 }, { "cid": 4045 } ] },
                "7287": { "name": "검투수 헤라클레이노스", …, "materials": [ { "cid": 7286 }, { "rule": "\"검투수\"라는 이름이 붙은 몬스터", "count": 2 } ] } } }
   ```
   `packs`는 발매일 오름차순이다. 파일은 팩 하나·카드 하나가 한 줄이다(diff용). `--reformat`은 받아 오지 않고 기존 파일을 이 형식으로만 다시 쓴다(소재 분리도 이때 한다. 이미 뗀 카드는 그대로).
5. 검증 출력: 팩 수(100), 팩별 카드 수/레어도 분포, 고유 카드 수, **이미지 미매칭 카드 목록**(미매칭은 수동 확인). 실패 시 non-zero 종료.
6. Konami 요청은 1초 간격.

- 버튼은 Liquid Glass 스타일: 주요 동작(구매·열기·모두 뒤집기)은 `.glassProminent`, 나머지(설정·판매 등)는 `.glass`. 패널·카드 배경에는 유리를 겹치지 않는다(`.fill.quinary`).

### 토큰 적립

- 토큰 = input + output + cacheWrite + cacheRead (PokeTokenBar와 동일).
- 집계 대상(`TodayUsageReader.read` = `TodayUsage.read`와 같은 결과, 이 Mac의 로컬 로그만. 오늘 바뀐 Claude JSONL은 수십~수백 MB라 파일마다 수정 시각·크기가 그대로면 다시 파싱하지 않고 메모리에 둔 결과를 쓴다. 쓰는 중인 세션 파일은 매번 통째로 다시 읽는다): Claude Code(`~/.claude/projects` 등), Codex(`~/.codex/sessions`·`archived_sessions`), Gemini, Grok(`~/.grok/sessions`), Pi(`~/.pi/agent/sessions`), oh-my-pi, Cursor. Cursor는 실앱·`PTB_PARITY=1`에서만 대시보드 API(`CursorUsageAPI`, Cursor 로그인 토큰)를 쓰고, 실패하거나 개발 실행이면 로컬 `state.vscdb`를 읽는다. API 캐시는 세이브 폴더의 `cursor-usage-api-cache.json`.
- 매 갱신마다 오늘의 provider별 누적 토큰을 구하고, `claimedToday.byProvider`와의 **양수 차이만** 적립한다. 날짜가 바뀌면 원장을 새로 시작한다 (PokeTokenBar `claimedTodayTokensByProvider` 방식).
- 첫 실행 시 오늘 누적치를 원장에 그대로 기록한다 → 설치 전 사용량은 적립하지 않는다.
- **원장은 같은 날 안에서 절대 내려가지 않는다.** 일시적으로 작은 값이 읽혀도 원장을 낮추지 않아야 나중에 같은 토큰을 두 번 적립하지 않는다.
- 적립된 delta는 `coinRemainder`에 더해 10,000 토큰마다 `coins += 1`로 환산하고(나머지는 이월), 같은 delta를 `dropProgress`(무료 카드용)에도 더한다.

### 저장

`~/Library/Application Support/YugiTokenBar/state.json`, 원자적 쓰기, 쓰기 전 직전 파일을 `state.json.bak`으로 보존.

```
{ coins, coinRemainder, dropProgress,
  owned: { cid: 보유 장 수(상한 없음) },
  claimedToday: { date, byProvider },
  pendingFree: <열지 않은 무료 카드 = 배지 숫자>,
  packStamp: <코인으로 산 팩 수, 10마다 0>, freePacks: <안 쓴 무료 팩>,
  favorites: [ 즐겨찾기 cid ],
  autoSellDuplicates: <설정: 중복 카드 자동 판매>,
  fusionOnly: <설정: 융합 몬스터는 융합으로만. 기본·키 없음 = false>,
  eraLimit: <설정: 시대 범위, 시대 이름. 기본·키 없음 = "GX">,
  partnerUnlocked: <파트너 해금. 「날개 크리보」를 처음 가질 때 true, 팔아도 유지. 기본·키 없음 = false>,
  partnerEnabled: <설정: 바탕화면 파트너. 기본·키 없음 = true>, partnerSize: <설정: 높이 pt 64~256, 기본 128>,
  partnerOrigin: <바탕화면 파트너 창 위치 [x, y]. 없으면 주 화면 오른쪽 아래>,
  decks: [ { id, name, cards: { cid: 장 수 } } ],
  log: [ 최근 획득 50건 { cid, source: "free"|"융합"|pid, date } ] }
```

- 빠진 키는 기본값으로 읽는다(필드를 추가해도 옛 세이브가 초기화되지 않게). `owned`는 JSON에서 `{"4007":2}` 형태다.
- 디코딩에 실패하면 원본을 `state.corrupt-<epoch>.json`으로 보관하고 `.bak`에서 복구한다. 둘 다 실패하면 새 상태로 시작한다.
- 환경변수 `YTB_STATE_DIR`가 있으면 그 폴더를 쓴다(개발·QA 때 실제 세이브와 분리).

### 내보내기·가져오기

- 내보내기 파일 `YugiTokenBar-Save-YYYYMMDD.json` = 봉투 `{ format: "yugitokenbar.save", schema: 1, appVersion, exportedAt, state }`. 상태 디코딩이 빠진 키를 기본값으로 채워 아무 JSON이나 읽히므로, 기본값이 없는 `format`/`schema`로 먼저 가린다. 8MB 초과, 다른 format, 더 높은 schema는 거부한다.
- 가져오기는 들어올 세이브와 지금 세이브의 수치(보유 종류 수, 코인)를 보여주고 확인을 받는다(Return = 취소). 바꾸기 전에 지금 세이브를 같은 봉투 형식으로 세이브 폴더(`YTB_STATE_DIR`를 따름)에 `state.import-backup-YYYYMMDD-HHmmss.json`으로 남긴다. 이 파일도 [가져오기]로 되돌릴 수 있다. 백업은 지우지 않는다.
- 적립 원장(`claimedDate`, `claimedByProvider`)은 이 Mac의 값을 유지한다. 다른 Mac의 원장을 쓰면 오늘 토큰을 다시 적립한다. 파트너 해금은 둘 중 하나라도 해금이면 유지하고, 파트너 표시 설정(`partnerEnabled`·`partnerSize`·`partnerOrigin`)도 이 Mac 값을 쓴다(`GameState.withLedger`).

## 5. 경제·뽑기 규칙

### 밸런스 상수

| 상수 | 값 |
|---|---|
| `tokensPerCoin` | 10,000 |
| `packPrice` | 1,000코인 (= 10M 토큰) |
| `packsPerFreePack` | 10 (코인으로 10팩 사면 랜덤 무료 팩 1개) |
| `tokensPerFreeCard` | 10,000,000 |
| `freeOpenBatch` | 5 (무료 카드 한 번에 여는 장 수) |
| `cardsPerPack` | 5 (노멀 4 + 레어 이상 1) |
| `monstersPerPack` | 2 (한 봉투에서 보장하는 몬스터 장 수) |
| `slot5Weights` | R 70% / SR 18% / UR 12% |
| `freeWeights` | 무료 카드: N 60% / R 25% / SR 10% / UR 5% |
| `sellPrice` | 1장당 N 30 / R 60 / SR 150 / UR 300 코인 |
| `maxCopiesInDeck` | 3 (덱에 같은 카드 최대 장 수, 유희왕 규칙. 미보유도 가능) |
| `deckSize` | 40~60 (메인 덱 권장 장 수, 표시만) |

하루 50M 토큰 → 무료 5장 + 5팩(25장).

### 무료 카드

`dropProgress`가 10M을 넘을 때마다 1장이 `pendingFree`에 **쌓이기만 한다**(자동으로 뽑지 않는다). 팝오버의 [무료 카드 N장 · 열기]를 누르면 최대 `freeOpenBatch`(5)장씩 **전체 8,172종에서 `freeWeights`로 티어를 고르고 그 티어 안에서 균등 무작위**로(티어가 비면 팩처럼 아래 → 위 티어로, 재수록 카드는 가장 높은 티어로 친다, 융합 전용 카드는 뺀다) 뽑아 패널 안 개봉 화면에서 보여준다. 보유 수 상한이 없어 이미 가진 카드도 나온다.

### 팩 구매

해금 없이 100팩 중 무엇이든(완료한 팩도) 살 수 있다. 코인으로 산 팩이 `packsPerFreePack`(10)개가 될 때마다 무료 팩 1개(`freePacks`)가 쌓인다. 팝오버의 [무료 팩 N개 · 열기]를 누르면 **정규 부스터 100팩 중 하나를 균등 무작위로** 골라 1봉투를 연다(개봉 화면 제목 "무료 팩 · 팩 이름"). 무료 팩으로 깐 건 다음 무료 팩 카운트에 세지 않는다. 한 번에 1팩씩만 사며, 버튼에는 가격(`ⓒ 1,000`)을 표시하고 코인이 부족하면 비활성화한다.
슬롯 1~4는 티어 1, 슬롯 5는 `slot5Weights`로 티어를 고른다. 슬롯 1~`monstersPerPack`(2)은 몬스터만 뽑아 한 봉투에 몬스터가 최소 2장 나온다(마법·함정만 나오는 봉투 없음). 모든 팩에 노멀 몬스터가 13장 이상이라 이 슬롯이 다른 티어로 올라가는 일은 없다(`CardDBTests`가 검증). 무료 카드에는 적용하지 않는다.

### 판매

컬렉션 창에서 보유한 카드를 1장씩 판다. 가격은 `sellPrice[티어]`이고, 여러 팩에 수록된 카드는 그중 가장 높은 티어로 친다. 0장이 되면 컬렉션에서 빠진다(마지막 1장은 확인 후 판매). 툴바의 [중복 모두 팔기]는 카드마다 1장만 남기고 나머지를 한꺼번에 판다(장 수와 받을 코인을 확인 후. 융합 전용 설정이 켜져 있으면 융합 소재는 필요한 최대 장 수만큼 남긴다(`Game.keep`, `CardDB.materialNeed`), 도움말과 확인창에도 그렇게 적는다). 팩 1개를 다 팔아도 기대값 ≈ 225코인이라 `packPrice`(1,000)보다 작다.

### 덱

컬렉션 창에서 덱을 여러 개 만든다. **미보유 카드도 넣을 수 있고**(목표 덱), 카드마다 `maxCopiesInDeck`(3)장까지다. 덱 장 수는 제한하지 않고 `deckSize`(40~60)는 권장으로만 보여준다. 덱 화면에서 보유 수가 덱에 넣은 장 수보다 적은 카드는 미보유처럼 흐리게 보여서 더 모아야 할 카드를 알 수 있다. 덱을 지워도 카드는 그대로다. 덱은 세이브(`decks`)에 저장된다.

### 융합

소재가 전부 100팩 카드인 융합 몬스터(83종. `Game.fusionMaterials`가 nil이 아닌 것, 소재 cid → 장 수)는 컬렉션 상세의 [융합]으로 만든다. 「융합」 마법 카드(`CardDB.fusionSpell` = 4837, 푸른 눈의 백룡의 전설 SR이라 어느 시대 범위에서도 구할 수 있다)를 1장 이상 가져야 열리고, 이 카드는 소비하지 않는다. 소재를 장 수만큼 소비하고(같은 카드 반복은 그만큼, `count`도 곱한다, 0장이 되면 컬렉션에서 빠진다) 1장을 받는다(`source: "융합"`, 중복 자동 판매는 적용하지 않는다). 소재가 모자라면 비활성. 설정 [융합 몬스터는 융합으로만](`fusionOnly`)이 켜져 있을 때만 버튼이 보이고, 그때 이 83종은 팩(`draw`)과 무료 카드(`drawFree`)에서 뽑히지 않는다(팩 진행도에는 그대로 들어가므로 완료하려면 융합해야 한다. 검투사의 급습은 UR이 융합 전용 1장뿐이라 UR 슬롯이 아래 티어로 내려간다). 소재 조건(`rule`)이나 100팩에 없는 소재(`name`)가 섞인 200종과 NEX 2종·베어트론은 설정과 무관하게 팩에서 나온다. 설정이 켜져 있으면 [중복 모두 팔기]와 중복 자동 판매는 소재를 범위 안 융합이 요구하는 최대 장 수(`CardDB.materialNeed`: 사이버 드래곤 3장)까지 중복으로 치지 않는다(`Game.keep`). 꺼져 있으면 1장만 남긴다. 어느 시대 범위에서도 융합 전용 카드의 소재는 같은 범위 안에 있어서(`CardDBTests`가 검증) 런타임에 범위 검사는 없다. 노멀 몬스터 보장은 융합 전용을 빼도 팩마다 13장 이상이라 그대로다.

### 카드 고르기 (`draw(pack, tier)`)

1. 해당 팩에서 그 티어이고 **같은 봉투에서 아직 나오지 않은** 카드 중(종류 제한이 있으면 그 종류만, 융합 전용 카드는 빼고, 보유 수 상한 없음) 균등 무작위로 고른다(한 팩 5장은 항상 서로 다르다).
2. 없으면 한 단계씩 **아래 티어**로 내려가고, 티어 1까지 없으면 **위 티어**로 올라간다.
3. 팩의 모든 카드를 1장 이상 가지면 "완료"(✓)로 표시한다. 완료해도 계속 살 수 있다.

### 완성 예상 (시뮬레이션, 2026-10-02 실데이터, 시드 5개)

VRAINS까지 75팩(6,160종)에서는 "무료 1장 + 1팩" 10,114~11,292회로 완성한다(27팩·2,270종일 땐 4,913~5,753회). 10M 단위이므로 약 1,000~1,100억 토큰이고, 로컬 사용량 추정 월 12억이면 **약 7~8년**이다. 마지막에 남는 UR(팩당 약 10종, 슬롯5 12%)이 대부분을 차지한다. 플레이어가 미보유가 가장 많은 팩을 산다고 가정했다. 실사용 후 상수로 조정한다.

SR·UR은 앞면이 드러날 때 연출이 있다(`RareEffect`): SR은 금빛 광택 한 번·빛 맥박·살짝 튀어오름, UR은 무지개 광택 반복·빛 고리와 반짝이 폭발·크게 튀어오름. [모두 뒤집기] → 다 뒤집으면 [확인] 옆에 한 번 더 버튼이 생긴다: 팩(무료 팩 포함)이면 [한 팩 더 · ⓒ 1,000](같은 팩을 코인으로 구매, 부족하면 비활성화), 무료 카드가 남아 있으면 [다음 N장 열기]. 둘 다 아니면 [확인]만 있다. Return 키는 뒤집기 → 한 번 더 순서로 걸린다. [확인]은 이전 화면(요약 또는 상점)으로 돌아간다. ‹ 로도 돌아간다.
- **컬렉션 창**: 왼쪽에 팩 목록("전체"·"즐겨찾기" 항목, 그 아래 상점과 같은 시대 섹션(DM~Modern). 섹션 헤더에 항상 보이는 꺾쇠·팩 수·보유/전체, 눌러서 접고 펴며 접힘 상태 기억. 팩마다 이미지·진행도 바), 가운데에 카드 그리드(툴바 검색창에서 한국어 카드 이름으로 검색(지금 고른 팩·전체·즐겨찾기 안에서, 대소문자·띄어쓰기 무시. 결과가 없고 전체가 아니면 빈 상태에 [전체에서 찾기] 버튼이 떠서 같은 검색어로 "전체"로 옮긴다), 그리드 위 필터 막대의 종류 메뉴로 모든 종류/몬스터/마법/함정(`attr`가 마법·함정이면 그 종류, 나머지는 몬스터), 구분선 아래 소환법 의식/융합/싱크로/엑시즈/펜듈럼/링크(몬스터의 `type` 칸에 그 이름이 있는 카드. 의식 마법은 의식에 안 들어가고, 엑시즈 펜듈럼은 둘 다에 들어간다), 등급 메뉴로 모든 등급/N/R/SR/UR만 보기, 정렬 메뉴로 팩 순서/높은 등급순/낮은 등급순/이름순/보유 많은 순(같으면 팩 순번), [미보유 카드 포함] 체크박스를 끄면 가진 카드만, 정렬은 기억, 체크박스는 기본 켜짐이고 창을 열 때마다 다시 켜짐, 카드 아래 한국어 이름 한 줄(넘치면 …, 미보유는 흐리게), 순번은 필터·정렬과 무관하게 팩 안 순번, 레어도, 2장 이상일 때만 ×2 표시, 이미지는 `cards_small`), 오른쪽에 상세 정보(큰 이미지, 한국어 이름, 그 아래 흐린 `callout` 두 줄 "어둠 · ★7 · 드래곤족/융합/효과"(랭크·링크는 "랭크 4"·"링크 4", 펜듈럼은 P스케일 포함)와 "ATK 2400 / DEF 1100"(링크는 ATK만), 그다음 "펜듈럼 효과"(펜듈럼만), "융합 소재"(융합만. 같은 소재가 반복되면 한 줄 "사이버 드래곤 × 3"(`count`도 곱한다). 100팩 카드는 링크 버튼이고 오른쪽에 "보유 N", 누르면 종류·등급·검색·미보유 필터를 풀고 그 카드를 골라 보이게 스크롤한다. 지금 범위에 없으면 "전체"로 옮긴다. 100팩에 없는 카드는 흐린 글자에 도움말, 조건은 흐린 글자 원문. 설정 [융합 몬스터는 융합으로만]이 켜져 있고 소재를 다 아는 융합이면 맨 아래 [융합] 버튼(「융합」 카드가 없거나 소재가 모자라면 비활성이고 도움말로 이유를 알린다. 「융합」이 없으면 그 아래 작은 링크 "「융합」 마법 카드가 1장 있어야 해요 (소비되지 않아요)"가 그 카드로 이동한다. 확인창에 소비할 소재 장 수. 5절 융합)), 제목 없는 효과 칸(비어 있으면 생략), 따로 묶은 한 줄 "보유 N장 … [1장 판매 · +ⓒ N]"(작은 버튼), 수록 팩과 레어도. 마지막 1장을 팔 때는 확인을 받는다). 카드에 마우스를 올리면 오른쪽 위에 ☆ 버튼이 생기고 누르면 즐겨찾기(★, 체크된 카드는 항상 표시, 미보유도 가능, 세이브에 저장). "즐겨찾기"는 즐겨찾기한 카드만 전체 순서대로 보여준다. 사이드바 맨 아래 **덱** 섹션: 헤더의 +로 새 덱("새 덱 N")을 만들고 덱마다 팩 줄처럼 이름·진행 바·"보유/덱 장 수"를 보여준다(보유는 카드마다 덱에 넣은 수와 보유 수 중 작은 쪽의 합, 다 모으면 초록). 그리드의 카드를 덱 줄로 **끌어다 놓으면**(줄이 강조됨) 그 덱에 1장 들어가고, 3장 한도에 걸리면 비프. 카드 우클릭 [덱에 추가 ▸ 덱 이름 · N장]으로도 넣는다(덱이 없으면 [새 덱에 추가]). 덱을 고르면 그리드에 덱의 카드가 팩 순서로 한 카드 한 칸(×장 수)으로 보이고 필터·정렬·검색은 그대로 동작하며, 부제는 "보유 / 덱 장 수장 보유 · 메인 덱 40~60장". 우클릭 [덱에 추가] 목록도 "덱 이름 · 보유/덱 장 수"다. 카드에 마우스를 올리면 왼쪽 위 −로 1장 빼고, 우클릭 [덱에서 1장 빼기]도 된다. 덱 줄 우클릭으로 이름 바꾸기(알림창)·삭제(확인, 보고 있던 덱이면 "전체"로). **여러 장 선택**: 클릭은 한 장, ⌘클릭은 토글, ⇧클릭은 마지막 클릭부터 범위 추가, 빈 곳에서 끌면 러버밴드(화면에 보이는 셀만, ⌘/⇧를 누르고 있으면 기존 선택에 더함), 빈 곳 클릭은 해제. Ctrl클릭은 macOS 우클릭이라 토글에 쓰지 않는다. 선택된 카드를 끌면 선택 전체가 함께 끌리고(미리보기에 장 수 배지) 덱 줄에 놓으면 각각 1장씩 들어간다. 우클릭 메뉴와 오른쪽 패널("N장 선택됨")의 [덱에 추가 (N장)]·[덱에서 1장씩 빼기 (N장)]도 선택 전체에 적용된다. 상세 정보는 한 장만 선택했을 때 보인다. 툴바 [전체 선택](⌘A)은 지금 보이는(필터·검색된) 카드를 모두 선택한다(러버밴드는 화면에 보이는 셀만 잡는 보완). 사이드바 선택이 바뀌면 선택은 비운다. 시대 범위는 설정에서만 바꾸고 컬렉션 창에는 메뉴도 안내도 두지 않는다. **미보유 카드는 흑백 실루엣**(grayscale 0.8, 밝기 -0.20)으로 보여주고, 마우스를 올리면 이름을 표시한다. 사이드바에서 마지막으로 고른 항목(전체·즐겨찾기·팩·덱)은 기억해서(`dex.scope`) 창을 다시 열면 그대로 열리지만, 그날(로컬 날짜) 처음 열 때는 "전체"로 연다(`dex.scopeDay`). 기억한 팩이 시대 범위 밖이거나 덱이 지워졌으면 "전체".
- **설정** (팝오버 내 화면 전환, 상점과 같은 방식):
  - 일반: [로그인 시 자동 실행] 스위치(`SMAppService.mainApp` 등록·해제, 세이브가 아니라 시스템에 저장). 설치한 `.app`에서만 켤 수 있고 `swift run` 개발 빌드에서는 비활성이다. 시스템이 승인을 요구하면 시스템 설정의 로그인 항목을 연다.

  - 카드: [중복 카드 자동 판매] 스위치(기본 끔, 세이브에 저장). 켜면 팩·무료 카드에서 이미 가진 카드가 나올 때 그 1장을 바로 `sellPrice`에 판다(보유는 그대로, 최근 획득 기록은 남음. 융합 전용 설정이 켜져 있으면 융합 소재는 필요한 장 수까지 쌓인 뒤에 판다). 개봉 화면에서 그 카드에 `+ⓒ N` 표시. 이미 쌓인 중복은 건드리지 않는다(컬렉션 [중복 모두 팔기]).
  - 카드: [융합 몬스터는 융합으로만] 스위치(기본 끔, 세이브 `fusionOnly`). 설명 줄에 지금 시대 범위에서 소재를 다 아는 융합 종 수. 켜면 5절 융합.

## 8. 테스트

`Tests/YugiTokenBarTests` (시드 고정 RNG 주입):
- 적립: 같은 누적치를 두 번 반영해도 한 번만 적립, 날짜 변경 시 원장 리셋, 첫 실행은 적립 0
- 코인과 무료 카드: 10M 경계, 나머지 이월
- 판매: 중복 자동 판매는 켰을 때 2장째부터만 팔고 끄면 다시 쌓인다
- 시대 범위: `DM`이면 팩·카드·보유 종 수·무료 카드·무료 팩이 DM 팩 안에서만, 해제하면 전체로 돌아온다; 범위 밖 중복은 팔리지 않고 덱 진행도·즐겨찾기 수에서 빠진다
- 뽑기: 보유 수 상한 없음, 티어가 비면 아래로 갔다가 위로 이동, 완료 팩도 구매 가능
- 해금 없음: 아무 팩이나 구매 가능, 마지막으로 산 팩(무료 카드 제외)
- 덱: 미보유 포함 카드당 3장 한도, 빼기·이름 바꾸기·삭제
- 융합: 설정을 켜면 중복 판매·자동 판매가 소재를 필요한 장 수만큼 남긴다; 「융합」 카드가 없으면 잠김, 소재를 장 수만큼 소비하고 1장 지급(「융합」은 남는다), 모자라면 거절, 소재를 모르는 융합은 못 만든다; 설정을 켜면 융합 전용 카드가 팩·무료 카드에서 안 나오고 UR 슬롯은 아래 티어로, 끄면 다시 나온다; 융합 전용 소재는 모든 시대 범위 안
- 저장: 왕복 직렬화, `.bak` 복구
- 데이터: `cards.json` 팩 100개(미니 팩 없음), 고유 8,172종, 시대 7개의 첫 팩 setCode(LOB·SOD·TDGS·REDU·DUEA·COTD·ROTD), 링크·펜듈럼 필드, 융합 소재(283종, 전부 cid 83종, "A"이나 "B"는 rule, 효과에 `＋` 없음), 모든 팩 cid가 `cards`에 존재
- 파트너: 시트 행별 프레임 수·셀 크기, 상태 판정 우선순위와 경계값(80%·1k·100k)·초기화 지난 한도 제외, 분당 토큰(첫 갱신·자정·감소 0, 1분 미만은 1분), 한 번 재생 큐(기준 상태 복귀·중복 방지·클릭 우선), 비행 방향 전환·기준 동작 사이 쉬기(범위 안)·한 번 재생 뒤 쉬지 않음·두리번, 메뉴바 깜빡임, 바탕화면 창 대체 위치(화면 밖·조금만 걸침·nil → 주 화면 오른쪽 아래)와 크기 제한(64~256, 192:208), 해금은 영구(가져오기 포함), 가져오기 때 파트너 표시 설정은 이 Mac 값, 시트가 없으면 파트너 끔, 새 키 없는 옛 세이브

## 9. 범위 밖 (YAGNI)

원격 서버 세션 적립, 다중 계정, 자동 업데이트(설정은 확인과 링크만), 업데이트 알림, 대결, 덱 순서 수동 편집·엑스트라 덱 구분, 레어도별 버전 수집, 스타터/스트럭처/프로모, 업적, 파트너 돌아다니기·커서 따라가기·호버 말풍선·저전력 모드 정지·다른 파트너 선택·메뉴바에서 기준 상태 동작 재생.
